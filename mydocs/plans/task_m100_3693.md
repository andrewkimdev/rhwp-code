## 1. 목표

`export-structure --mode clause`가 가지번호 조문의 marker를 온전히 보존하고 괄호형 `호`/`목`
표기를 인식하게 한다. 동시에 일반 문서의 날짜·목차·번호 목록을 법령 `호`/`목`으로 과검출하지 않도록
구조 문맥을 수용 기준으로 고정한다.

## 2. 최신 기준선

최신 `devel`과 실제 저장소 sample에서 다음을 확인했다.

- `제1조의2(정의)`는 `조`로 검출되지만 marker는 `제1조`로 잘린다.
- `1)`, `가)`는 후보로도 검출되지 않는다.
- `samples/2022년 국립국어원 업무계획.hwp`의 날짜형 `2022. 1.`이 `호` 한 개로 검출된다.
- `samples/2025 행정업무운영 편람(최종).hwp|hwpx`의 장·절 아래 목차 번호가 `호` 75개로 검출된다.
- `samples/hwp3-sample16-hwp5.hwp`의 공동수급 협정서 구간은 `제1조` 아래 `1.`~`3.`을 실제
  `호` 구조로 사용한다.
- 기존 structure 단위 테스트 3건, CLI JSON 계약 4건, 종료 코드 focused 테스트는 통과한다.

## 3. 설계 결정

텍스트 패턴 검출과 구조 노드 채택을 분리한다.

1. `제N조` 뒤에 `의M`이 이어지면 전체를 marker로 보존한다.
2. `N.`/`N)`과 `가.`/`가)`를 각각 `호`/`목` 후보로 검출한다.
3. `호` 후보는 현재 열린 clause stack에 `조` 또는 `항`이 있을 때만 노드로 채택한다.
4. `목` 후보는 현재 열린 clause stack에 `호`가 있을 때만 노드로 채택한다.
5. `편`/`장`/`절`/`관`/`조`/원문자 `항`은 기존 strong marker로 유지한다.

이 규칙은 명시적 clause 모드에서 법령 계층의 부모 증거를 요구하므로 standalone 날짜·목차 번호를
거부하면서 실제 협정서의 `조 → 호`, `조 → 항 → 호` 구조를 보존한다.
