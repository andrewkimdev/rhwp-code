# 수행계획서 — #3888 CI slow shard 분리와 일반 7-shard 재분배

- 이슈: [#3888](https://github.com/edwardkim/rhwp/issues/3888)
- 기준 브랜치: `upstream/devel` `85d334728`
- 작업 브랜치: `task/3888-ci-slow-shard`
- 실측 기준: PR #3741 CI run `30810987621`

## 문제

현재 default-feature 테스트는 `hash:m/8`로 8개 worker에 나뉜다. 실행 건수는 602~651건으로
가깝지만 shard 3은 `overflow_cell_lines_do_not_grow`(133.510초), HWP5 전수
roundtrip(52.407초), 대형 HWP5 roundtrip(29.499초)이 함께 배치되어 nextest Summary가
168.457초였다. 다른 shard는 10.331~55.550초였다.

## 구현 계획

1. 기존 `test-shard` 단일 matrix를 유지하고 worker 수를 8개로 고정한다.
2. matrix에 `slow shard` 1개와 `shard 1/7`~`shard 7/7`을 명시적으로 선언한다. 단일 matrix를
   유지해 `fail-fast: true`가 여덟 worker 전체에 적용되게 한다.
3. slow worker는 `rhwp::overflow_cell_baseline` binary의
   `overflow_cell_lines_do_not_grow`만 실행한다. 일반 worker는 같은 filterset의 여집합을
   선택하고 `hash:m/7`로 분배한다.
4. 모든 worker가 서로 다른 count artifact를 남기고, 기존 `Build & Test` 집계가 여덟 artifact의
   실행 건수 합계를 archive 단계의 runnable 수와 계속 대조한다.
5. CI 구조 문서의 8-shard 설명을 1 slow + 7 일반 shard로 정정한다.

## 수용 기준

- `Default-feature tests (slow shard)`와 `Default-feature tests (shard 1/7)`~`(shard 7/7)`이
  같은 `test-shard` matrix에서 시작한다.
- 일반 worker는 slow 테스트를 실행하지 않고 slow worker는 해당 테스트만 실행한다.
- count artifact는 정확히 8개이며 실행 건수 합계가 전체 runnable 수와 일치한다.
- workflow 구문 및 filterset 선택 계약을 로컬에서 검증하고, PR 최신 head의 GitHub Actions에서
  전체 CI 성공을 확인한다.

## 위험과 완화

- `hash:m/7`은 기존 `hash:m/8`과 다른 배치를 만든다. 변경 PR의 실제 shard Summary 시간을
  기록해 예상보다 긴 일반 shard가 새로 생기지 않았는지 확인한다.
- 단일 133초 테스트는 더 쪼개지지 않으므로 완전한 시간 균등화는 불가능하다. 전용 worker로
  임계 경로를 현재 168초에서 약 133초로 줄이는 것이 이번 범위다.
