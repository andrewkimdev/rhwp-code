## 1. 문제

현재 `CI`는 review-only fast-pass와 단일 `frontend_required`만 구분한다. 따라서 Studio 단축키나
명령 정책처럼 Rust·WASM·렌더 출력과 무관한 변경도 Rust lint, 세 builder가 만드는 네 test archive,
네 worker, Native Skia와 Canvas, Rust/Python CodeQL까지 실행한다. Rust 검증의 결함 검출력은 유지하되
관련 없는 변경에서만 worker를 생략하려면 frontend 여부가 아닌 독립 영향축이 필요하다.

#3892는 default-feature test를 `slow/1/2/3` 네 archive와 세 builder·네 worker로 재배치해 wall time을
줄였지만 변경 영향과 무관한 worker 실행 자체는 유지한다. 따라서 이 계획의 가치는 남아 있으며,
후속 조건화와 artifact retry는 #3892 이후 topology를 기준으로 설계한다. Stage 2에서 기록한 8-shard
runner-minute는 당시 topology의 historical 수치로만 보존한다.

## 2. 목표 출력

classifier는 다음 값을 하나의 판정으로 만든다.

| 출력 | 값 | 의미 |
| --- | --- | --- |
| `rust_required` | `true|false` | Rust lint·default test 필요 여부 |
| `frontend_mode` | `none|unit|package` | Studio 전역 typecheck·단위 gate 또는 전체 package gate 범위 |
| `render_required` | `true|false` | Canvas visual diff와 CanvasKit readiness를 포함한 Render Diff 필요 여부 |
| `native_skia_required` | `true|false` | Native Skia 검증 필요 여부 |
| `codeql_languages` | 언어 CSV 또는 `none` | JavaScript/TypeScript·Python·Rust 분석 범위 |
| `classification_status` | `classified|full` | 정상 분류 또는 fail-closed 전체 검증 |
| `classifier_version` | 정수 문자열 | 판정 규칙 버전 |
| `reason` | 안정된 reason 목록 | 실행 기록과 회귀 분석 근거 |

## 3. 안전 경계

- 첫 PR은 shadow 판정과 summary만 추가한다. 기존 `frontend_required`와 모든 worker `if` 조건은 유지한다.
- classifier·workflow·Cargo 변경, `src/main.rs`, rename, 빈 파일 목록, API 오류, PR 3,000개 및 push
  300개 경계, 미분류 경로는 `classification_status=full`로 닫는다.
- rename은 현재 경로와 이전 경로를 모두 평가하되 Stage 1에서는 전체 검증 판정으로 고정한다.
- Stage 1·2의 pull request merge ref classifier는 advisory로만 취급한다. Stage 2.5부터 PR base SHA의
  classifier를 실행하고 `pr-base-trusted-shadow` authority로 별도 표본을 누적한다.
- Stage 2.5가 base SHA에 고정하는 것은 classifier 파일 하나뿐이다. `pull_request` workflow YAML,
  인라인 collect script, classifier 호출부와 후속 worker `if`는 PR merge ref의 제어를 받으므로
  `pr-base-trusted-shadow`를 실제 skip 권한으로 해석하지 않는다.
- 실제 skip 전에는 trusted controller/required policy check를 두거나, 신뢰되지 않은 fork·head 경로를
  계속 full로 닫는 Stage 2.6 실행 경계를 먼저 확정한다.
- review-only fast-pass와 required check 이름 `Build & Test`의 의미는 바꾸지 않는다.
- `src/main.rs`는 #3789에서 render/export 진입점이 모듈화되기 전까지 render 포함 full로 처리한다.
- `frontend_mode=unit`도 `rhwp-studio/tsconfig.json`의 전체 `src`를 대상으로 하는 `tsc --noEmit`과
  전체 Studio unit test를 실행한다. `package`는 이 계약에 Vite·extension·package build를 추가한다.
- 현재 Render Diff workflow는 좁은 Canvas visual diff와 Studio 앱 전체를 띄우는 CanvasKit readiness를
  함께 실행한다. 활성화 전에는 두 gate의 영향축을 분리하거나 실제 의존 경로의 보수적 합집합을
  `render_required`로 확정한다. 경로·파일명 heuristic만으로 skip하지 않는다.

## 4. 단계와 조정된 실행 순서

1. **Stage 1 — shadow classifier와 fixture**: #3785, #3656, #3670, #3672, #3690의 실제 파일
   목록을 fixture로 고정하고 판정만 기록한다.
2. **Stage 2 — shadow 관찰**: PR별 예상 worker와 실제 worker 결과를 대조하고 false negative가 없음을
   확인한다.
3. **Stage 2.5 — trusted-base shadow**: PR base SHA의 classifier를 실행하되 worker 조건은 그대로 두고,
   classifier-source authority의 운영 표본을 새로 누적한다.
4. **Stage 2.6 — trusted enforcement boundary**: workflow 제어면까지 신뢰할 수 있는 controller 또는
   required policy check를 설계한다. 이를 도입하지 않는 PR 유형은 full로 유지하며, Stage 2.5 authority
   하나만으로 worker skip을 허용하지 않는다.
5. **Stage 3 — frontend 축 활성화**: `unit`, `package`, `render`를 분리하고 aggregate에서
   `success|skipped` 진리표를 검증한다.
6. **Stage 4 — Rust·Native Skia 조건화**: Rust 비영향 PR에서 lint와 세 builder·네 worker를,
   render 비영향 Rust PR에서 Native Skia를 생략한다. aggregate는 각 builder/worker의
   `success|skipped` 조합을 영향축별 진리표로 검증한다.
7. **cache 회귀 확인**: #3684를 완료한 #3810의 정리 직후 기준선 4.73GB와 Stage 4 이후 다음 cache sweep
   직후 총량을 같은 시점 조건으로 대조한다. 기준선 회귀가 없으면 별도 대기 없이 다음 단계로 진행한다.
8. **Stage 5 — CodeQL 언어 분리**: 고정된 4.73GB 기준선 회귀 여부를 확인하며 workflow별 언어 축을
   활성화한다.
9. **Stage 6 — artifact retry**: 논리 label `slow/1/2/3`별 test archive, archive expected count와
   worker run count의 primary/retry 중 하나 이상을 aggregate에서 인정한다.
10. **Stage 7 — draft 경량화**: draft에는 영향별 경량 검증을 수행하고 `ready_for_review`에서 최종 검증을
   보장한다.

각 활성화 단계는 별도 PR로 진행한다. Stage 2.5에서도 skip을 활성화하지 않고,
`pr-base-trusted-shadow` 관찰 자료와 Stage 2.6 실행 경계가 충분하지 않으면 Stage 3로 넘어가지 않는다.

## 7. 검증

node --test scripts/tests/ci-impact-classifier.test.cjs
python3 -m unittest scripts/tests/test_ci_impact_workflow.py
