## 핵심 발견 (진단의 가치가 수정보다 크다)

1. **편차 +3 은 양방향 상쇄의 착시** — 실제 발산은 rhwp 전용 11쪽 + 한컴 전용 8쪽
   = 19쪽 규모. 총량 지표는 문제를 1/6 로 과소평가하며, 이것이 픽셀·PI 집계 지표가
   4개월간 정체된 구조적 이유의 실증이다.
2. **블록 높이·간격·전진량은 이미 정합** — Q&A 표 26개 중 25개 선언 일치, 문단 전진
   3건 완전 일치(269.3/318.4/248.6px). 편차의 실체는 **"어떤 표를 쪽 경계에서
   분할하느냐"의 진입 판정**이다.
3. **게이트 특정**: `declared_overflows_current`(typeset.rs ~18029) — 빈 host RowBreak
   다행 표를 declared(저장 최소 셀합) 기준으로, **0.1px 차이로도** 분할 검토 없이
   통짜 이월(pi=14: 741.9 > 관용 741.8). 한컴은 같은 지점에서 행 분할로 잔여
   174px 를 채웠다(head 178.6px, 저장 vpos 로 실증).

## 수정 — 저장 되감김 증거 형상

`saved_anchor_splits_here` 에 두 번째 저장-증거 형상 추가: **다음 문단의 저장 vpos 가
표 앵커보다 되감기고 그 크기가 실측 표 높이보다 작으면**, 원본 한글이 이 지점에서 행
분할했다는 증거이므로 declared 선이월을 건너뛰고 분할 경로로 보낸다. row_count>1 로
1×1 그림 표(#874·#2439) 보호, 기존 #2097 형상 불변.

구현 중 자체 검출 결함 1건: 꼬리 크기를 declared 와 비교(항상 탈락) → 실측
table_total 로 정정.
