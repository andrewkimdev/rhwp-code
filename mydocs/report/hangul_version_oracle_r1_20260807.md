- **표본**: `D:\hwpdocs_10k_share` 10,000건 (.hwp 6,582 / .hwpx 3,418) — 10k 서베이와 같은 코퍼스
- **오라클**: 한컴오피스 한글 **2022 (12.0.0.535)** ↔ **2024 (13.0.0.564)**, COM 자동화
- **결과**: **247건(2.47%)** 이 두 버전에서 다르게 페이지네이션된다. 9,746건은 동일하다.

rhwp의 1차 정답지는 한컴 편집기다. 그런데 편집기 버전이 둘이고 둘의 판정이 갈리면, 정답지 자체가
갈라진다. 이 측정은 **어느 문서에서 정답지가 갈라지는지**를 전수로 확정한 것이다.

## 1. 측정 지표 — 쪽수가 아니라 페이지네이션 지문

쪽수만 비교하면 "쪽수는 같은데 쪽 나눔 위치가 다른" 경우를 놓친다. 문서마다 지문을 뽑아 통째로 비교했다.

```text
문단 0..N 을 SetPos 로 훑으며 XHwpDocumentInfo.CurrentPage 를 읽고,
쪽이 바뀌는 지점만 남긴 런렝스 목록  =  "쪽@시작문단, 쪽@시작문단, ..."
```

`tools/verify_pi_page_vs_hangul.py`의 per-PI 쪽위치와 같은 계약이다. 판정 분류는 세 가지다.

| 분류 | 뜻 | 건수 |
| --- | --- | --- |
| `PAGE_DELTA` | 총 쪽수가 다름 | 121 |
| `BREAK_DIFF` | 쪽수는 같으나 쪽 나눔 위치가 다름 | 123 |
| `PARA_DIFF` | 문단 수 자체가 다름(문서를 다르게 읽음) | 3 |
| | **합계** | **247** |

## 2. 버전 전환 — 같은 CLSID를 HKCU로 갈아끼운다

한글 2022와 2024는 **같은 CLSID** `{2291CF00-64A1-4877-A9B4-68CFE89612D6}`를 공유하고,
HKLM 등록은 나중에 설치된 2024를 가리킨다. 관리자 권한 없이 전환하려고 HKCU 오버라이드를 썼다 —
COM 활성화에서 HKCU가 HKLM보다 우선한다.

```text
HKCU\Software\Classes\CLSID\{2291CF00-...}\LocalServer32
HKCU\Software\Classes\Wow6432Node\CLSID\{2291CF00-...}\LocalServer32
  = "C:\Program Files (x86)\Hnc\Office 20XX\HOffice1X0\Bin\Hwp.exe -Automation"
```

전환이 실제로 일어났음을 세 겹으로 확인했다 — `hwp.Version` 반환값, 실행 중인 프로세스 경로,
그리고 워커가 인스턴스를 만들 때마다 major 버전을 검증하고 불일치 시 즉시 종료(`exit 3`)한다.
전 실행에서 버전 불일치 종료는 0건이었다. 측정 후 HKCU 오버라이드는 제거해 원래 상태로 되돌렸다.

## 3. 측정 조건 — **한글 COM 인스턴스를 병렬로 띄우면 안 된다**

이 측정에서 가장 값비싼 발견이다. 처음에는 워커 5개 병렬로 돌렸고 10,000건 중 **3,573건이 "다름"** 으로
나왔다. 대부분 거짓이었다.

| 검증 | 결과 |
| --- | --- |
| 같은 버전(2024)·같은 200문서를 **워커 1개 vs 5개**로 측정 | **36건(18%) 불일치** |
| 문서마다 새 인스턴스(hermetic) vs 인스턴스 1개 유지(워커 1개) | **200/200 완전 일치** |
| 병렬 실행에서 인스턴스 내 처리 순서 구간별 차이율 | 16.7% ↔ 62.0% 로 요동 |
| 같은 조건(워커 5개) 2회 반복 | 불일치 0 |

즉 한글 COM은 **인스턴스를 동시에 여러 개 띄우면 같은 문서에 다른 페이지네이션을 낸다.** 정확도에
필요한 것은 "문서마다 새 인스턴스"가 아니라 **동시 실행 금지**뿐이다. 인스턴스는 오래 유지해도 된다.

주의할 함정: 같은 조건을 두 번 돌리는 자기일관성 시험은 **이 오염을 잡지 못한다.** 오염이 처리
순서에 대해 결정적이라 두 실행이 똑같이 틀리기 때문이다. 병렬도를 바꿔 대조해야 드러난다.

따라서 본 측정은 `-Workers 1 -RecycleEvery 0`(버전당 인스턴스 1개)로 수행했다.
소요는 2022 약 22분, 2024 약 28분이다. 병렬 5개는 약 15분으로 빠르지만 결과를 쓸 수 없다.

## 7. 어느 버전을 정답지로 둘 것인가

**2022를 1차 정답지로 유지한다.**

- 저장소의 기존 기준선이 사실상 2022다 — `pdf/*-2022.pdf` 계열 baseline, 10k 서베이 기준선
  [r23](../manual/memory/project_survey_baseline_r23.md), TAC 검증이 모두 2022 기준이다. 2024로 옮기면
  r30↔r31처럼 **문서 단위로 직접 대비하는 시계열이 끊긴다.**
- 두 버전 차이는 2.47%로, 이전이 주는 정확도 이득보다 기준선 단절 비용이 크다.
- 2024는 **보조 오라클**로 쓴다. 위 247건은 곧 "한컴이 판정을 바꾼 지점"이라, rhwp가 어느 쪽을 따라야
  하는지 검토할 후보 목록이다. 특히 5.1의 상위 사례는 장문 보고서의 누적 오차가 드러나는 지점이라
  레이아웃 조사 대상으로 값이 크다.

5.5의 분포는 이 판단을 같은 방향으로 뒷받침한다. 이 코퍼스는 **이미 배포가 끝난 공공문서**이고, 그중
2024로 저장된 것은 1.0%뿐이다. 이 문서들은 다시 조판되지 않으므로, 최신 편집기가 조판을 바꿔도 이미
배포된 문서는 따라 바뀌지 않는다. 재현 대상이 "지금 설치된 편집기의 조판"인지 "배포 시점의 조판"인지에
따라 답이 갈리며, 후자라면 2024로 옮기는 것은 개선이 아니라 원본과의 이격이 된다.

다만 이 결론에는 **아직 채우지 못한 데이터가 둘** 있다. 어느 쪽으로도 확정하기 전에 짚어 둔다.

1. **어느 쪽이 더 맞는가.** 247건에 대해 어느 버전이 옳은지는 판정하지 않았다. rhwp가 현재 어느 쪽과
   일치하는지 집계하면 교체 비용을 수치로 알 수 있고, 차이가 큰 상위 사례는 사람이 열어 시각 판정해야 한다.
2. **현재 설치 점유율.** 정답지의 목적이 "우리 출력이 사용자 화면과 같은가"라면 기준은 최신판이 아니라
   현장에 가장 많이 깔린 버전이어야 한다. 그 자료는 없다.

5.5에서 최빈이 한글 2020(70.7%)으로 나온 것도 그대로 남겨 둘 문제다. 대조를 2022↔2024 둘로 좁힌 것이
맞는지, **2020(major 11)까지 포함한 3자 대조**가 필요한지는 별도 판단이 필요하다. 이번 측정 환경에는
2020이 설치되어 있지 않아 재지 못했다.

이 결정은 [Discussion #4137](https://github.com/edwardkim/rhwp/discussions/4137)에서 의견을 구하는 중이다.

## 8. 부수 관찰

- `RegisterModule("FilePathCheckDLL", "FilePathCheckerModule")`은 **False**(모듈 미등록, DLL이 시스템에
  없음)지만, 10,000건 × 2버전 전 구간에서 파일 접근 보안 대화상자는 **한 번도 뜨지 않았다.**
  `SetMessageBoxMode(0x00020000)`만으로 무인 실행이 가능했다.
- 자동화 중 화면에 뜨는 것은 한글 메인/스플래시 창뿐이고, COM 인스턴스를 만들 때마다 나타난다.
  Win32 `ShowWindow(SW_HIDE)`로 이 창을 숨기려는 시도는 **자동화를 교착시킨다** — 워커 전원이 첫
  문서에서 정지했고 숨김을 중단하자 즉시 재개됐다. 창은 COM `XHwpWindows.Visible = false`로만 다룬다.
- 측정 실패는 2022 0건 / 2024 1건으로, 개방 안정성은 두 버전이 사실상 같다.
- **버전 전환을 무효로 만드는 것이 둘 있다.** 하니스를 저장소에 넣으면서 실측으로 확인했다.
  ① 남아 있는 `Hwp.exe` — 이미 떠 있는 인스턴스가 있으면 COM은 오버라이드와 무관하게 그 인스턴스에
  붙는다. ② **HKCU CLSID 키 삭제** — 지우면 그 로그인 세션 동안 COM이 HKCU를 아예 무시하고, 값을 다시
  써도 소용없으며 로그오프 후 재로그인해야 복구된다. 그래서 정리 스크립트는 키를 지우지 않고 값을 기계
  기본값으로 되돌린다. 두 경우 모두 `page_oracle_run.ps1`이 패스 시작 시 COM을 한 번 띄워 확인하고 즉시
  중단한다. r1 측정 자체는 이 문제 발생 이전에 끝났고, 워커가 인스턴스마다 major를 검증해 최종 패스의
  버전 불일치가 0건이므로 위 결과는 영향받지 않았다.

## 9. 산출물

하니스는 저장소에 있다 — [`tools/hangul_version_oracle/`](../../tools/hangul_version_oracle/).
재현 절차는 [한글 버전별 페이지네이션 대조 가이드](../manual/verification/hangul_version_oracle.md)를 따른다.
코퍼스 공유본 링크도 그 가이드 3절에 있다.

측정 원자료는 `output/poc/hangul_2022_vs_2024_20260807/` (gitignore)

| 파일 | 내용 |
| --- | --- |
| `diff_confirmed.tsv` | 확정 차이 247건 — `kind / path / detail` |
| `diff_unconfirmed.tsv` | 확정하지 못한 7건 |
| `fingerprint_2022.tsv`, `fingerprint_2024.tsv` | 10,000건 전체 원시 지문 |
| `appversion.tsv` | 10,000건 작성 앱·포맷 버전 — `path / kind / app / format` |
| `corpus_10k.txt` | 표본 목록 |

재현(가이드 요약):

```powershell
powershell -File tools\hangul_version_oracle\list_hangul_versions.ps1
powershell -File tools\hangul_version_oracle\page_oracle_run.ps1 -HwpVersion 2022 -ListPath corpus_10k.txt -OutDir pass2022 -Root 'D:\hwpdocs_10k_share'
powershell -File tools\hangul_version_oracle\page_oracle_run.ps1 -HwpVersion 2024 -ListPath corpus_10k.txt -OutDir pass2024 -Root 'D:\hwpdocs_10k_share'
powershell -File tools\hangul_version_oracle\compare_passes.ps1 -DirA pass2022 -DirB pass2024 -LabelA 2022 -LabelB 2024 -OutPath diff.tsv
powershell -File tools\hangul_version_oracle\restore_com_default.ps1
```
